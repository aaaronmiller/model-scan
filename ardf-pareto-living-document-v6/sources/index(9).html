The table defines the model universe. The graphs reveal which points survive.

Cost per token cannot answer a delegation question because the bill is created by the whole task: tokens consumed, retries, tool loops, validation, and the probability that the result is accepted. This report therefore starts with the authoritative model table, not a decorative chart. Figure 1 then plots every native Claude Code configuration so the family curves and their dominated “zags” remain visible. Figure 2 maps every supplied model onto a common accepted-cost scale, places exact or calibrated Artificial Analysis intelligence on the vertical axis, and draws only the observed non-dominated upper boundary. The resulting line is the delegation list: at any cost budget, it identifies the highest measured intelligence that the evidence supports.

No silent omissions: exact external values are marked exact. Lower-effort Claude points absent from the supplied AA CSV are derived from the real effort-profile reference graph and anchored to exact AA maximum-effort records. Cross-dataset values carry their calibration equation, anchor count, and confidence in the tooltip and tables.

Method · no arbitrary averaging

How the datasets are placed on one cost and intelligence scale

Each cost source is converted to the extended SkateBench cost-per-success scale by the median multiplicative ratio observed on exact model-ID overlaps. The median is used because one provider or benchmark run can be an extreme outlier. Intelligence uses a two-stage bridge: official or v2 task success is first mapped onto the extended score with robust regression, then the extended score is mapped onto the AA Intelligence Index using exact overlapping AA rows. The latter fit is weak and is therefore marked low confidence rather than presented as exact IQ.

Live refinement

Proxy telemetry that replaces static assumptions

The proxy should log one record for every call and one aggregate record for every accepted task. At call level, record provider, canonical model ID, effort, skill stack, prompt version, task class, input and output tokens, cached and reasoning tokens when exposed, tool calls, latency, provider cost, quota delta, validator result, retry number, and error type. At task level, record the complete escalation path, first-pass success, final acceptance, total cost, total latency, human correction count, and validation evidence.

The live router then groups outcomes by task class × model × effort × skill stack × provider, calculates total cost divided by accepted tasks, and compares that empirical value with the benchmark coordinate shown here. Calibration benchmarks prevent easy-task assignment bias; rolling windows detect provider or model drift. A route is promoted only after sufficient validated samples and is quarantined only for the task class in which it failed.
